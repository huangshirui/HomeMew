# HomeMew 微信小程序

# HomeMew 家事喵微信小程序需求

## 1. 产品定位

家事喵微信小程序是 HomeMew 面向家庭成员的主要图形化操作端。

主要用于：

* 用户登录和身份初始化；
* 创建或加入家庭；
* 管理家庭成员；
* 查看和维护家庭日程；
* 查看和维护家庭待办任务；
* 接收并打开通知对应的业务详情；
* 提供传统 GUI，补充智能助手自然语言交互不方便完成的操作。

小程序不是独立业务系统。

家庭、成员、日程、待办等业务数据统一存储在 HomeMew Core 中，小程序通过 Core API 读写数据。

---

# 2. 第一版用户范围

初期主要服务一个家庭：

```text
1 个主要家庭
最多 8 名家庭成员
```

系统能力仍支持：

```text
一个微信用户最多创建 3 个家庭
一个用户可以加入多个家庭
```

用户进入小程序后，可以在自己已加入的家庭之间切换。

# 3. 系统架构

## 3.1 推荐调用链路

### 登录和身份初始化

```text
微信小程序
→ 微信云函数
→ 获取可信 openid
→ 查询微信身份与 HomeMew user_id 的映射
→ 必要时调用 Core 创建用户
→ 签发短期 HomeMew JWT
→ 返回小程序
```

### 日常业务调用

```text
微信小程序
→ 携带 HomeMew JWT
→ 直接调用 Cloudflare Worker Core API
```

### 微信平台专属能力

```text
微信小程序
→ 微信云函数
→ 微信服务端 API
```

包括：

* 获取可信微信身份；
* 生成小程序码；
* 获取微信平台访问令牌；
* 发送订阅消息；
* 解密微信敏感数据；
* 其他必须使用微信服务端凭证的操作。

## 3.2 小程序不应保存

```text
JWT_SECRET
Core 服务 Token
n8n 服务 Token
微信 appsecret
企业微信 secret
```

小程序只保存短期用户访问 Token。

# 4. 身份与登录

## 4.1 首次进入

用户第一次打开小程序时，小程序自动调用登录云函数。

登录云函数：

1. 从微信运行环境取得 `openid`；
2. 查询身份映射；
3. 如果不存在映射，调用 Core 创建 HomeMew 用户；
4. 保存 `openid → HomeMew user_id` 映射；
5. 签发短期用户 JWT；
6. 返回登录结果。

返回建议：

```json
{
  "accessToken": "eyJ...",
  "expiresAt": "2026-07-21T18:00:00+08:00",
  "isNewUser": true
}
```

## 4.2 获取用户信息

登录完成后调用：

```http
GET /api/v1/me
```

用于获取：

* HomeMew 用户 ID；
* 昵称；
* 头像；
* 用户状态。

## 4.3 首次完善资料

新用户第一次进入时，需要设置：

* 用户昵称；
* 用户头像，可选。

调用：

```http
PATCH /api/v1/me
```

示例：

```json
{
  "displayName": "KK爸爸",
  "avatarUrl": "https://..."
}
```

昵称用于家庭成员列表、日程参与人和待办负责人展示。

## 4.4 Token 过期

Core 返回 `401` 时：

```text
小程序重新调用登录云函数
→ 获取新 Token
→ 原请求自动重试一次
```

不建议第一版实现独立 Refresh Token。

## 4.5 用户被禁用

如果 Core 返回用户已被禁用：

* 清除本地 Token；
* 停止访问业务页面；
* 展示账号不可用提示；
* 不进入无限重试登录。

# 6. 启动流程

## 6.1 普通启动

```text
启动小程序
→ 恢复本地 Token
→ Token 不存在或即将过期则调用登录云函数
→ GET /api/v1/me
→ GET /api/v1/me/families
```

根据家庭数量处理：

### 没有家庭

展示：

```text
创建家庭
加入家庭
```

### 只有一个家庭

直接设置为当前家庭并进入首页。

### 多个家庭

优先恢复上次使用的家庭。

如果上次家庭已无权访问，则：

* 自动选择第一个有效家庭；
* 或展示家庭选择页。

## 6.2 从邀请链接进入

用户通过分享卡片、小程序码或二维码进入时，启动参数可能包含：

```text
code=HM-8K2Q-P7MX
```

流程：

```text
完成登录
→ GET /api/v1/family-invites/{code}
→ 展示邀请确认页
→ 用户确认
→ POST /api/v1/family-invites/{code}/join
→ 设置为当前家庭
→ 进入家庭首页
```

## 6.3 从通知进入

企业微信通知或未来小程序通知可能打开：

```text
pages/events/detail?id=evt_123&familyId=fam_123
```

或：

```text
pages/tasks/detail?id=tsk_123&familyId=fam_123
```

流程：

```text
完成登录
→ 调用对应详情 API
→ Core 校验家庭权限
→ 展示详情
```

如果用户已被移出家庭：

* 展示“你已无权查看该内容”；
* 不泄露日程或待办内容。

# 7. 家庭功能

## 7.1 获取家庭列表

调用：

```http
GET /api/v1/me/families
```

展示：

* 家庭名称；
* 家庭头像；
* 当前用户角色；
* 家庭成员数量。

## 7.2 创建家庭

入口：

```text
首页无家庭状态
我的 → 创建家庭
家庭切换器 → 创建家庭
```

表单字段：

```text
家庭名称：必填
家庭头像：可选
```

调用：

```http
POST /api/v1/families
```

创建成功后：

* 创建人自动成为管理员；
* 设置新家庭为当前家庭；
* 进入家庭首页；
* 引导邀请家人。

达到 3 个家庭创建上限时，展示明确提示。

## 7.3 家庭切换

家庭切换器展示当前用户加入的所有有效家庭。

切换后：

* 更新本地 `currentFamilyId`；
* 刷新首页；
* 刷新日程；
* 刷新待办；
* 刷新成员信息。

当前家庭 ID 只是界面上下文，不是权限凭据。

## 7.4 家庭详情

调用：

```http
GET /api/v1/families/{familyId}
```

展示：

* 家庭名称；
* 家庭头像；
* 成员数量；
* 当前用户角色；
* 创建时间；
* 创建人，可选展示。

## 7.5 修改家庭资料

仅管理员显示编辑入口。

调用：

```http
PATCH /api/v1/families/{familyId}
```

支持修改：

* 家庭名称；
* 家庭头像。

普通成员不显示编辑入口。

即使前端错误展示，Core 仍必须返回 `403`。

# 8. 家庭成员功能

## 8.1 成员列表

调用：

```http
GET /api/v1/families/{familyId}/members
```

展示：

* 头像；
* 昵称；
* 管理员标识；
* 加入时间，可选。

管理员和普通成员都可以查看。

## 8.2 邀请成员

仅管理员可使用。

调用：

```http
POST /api/v1/families/{familyId}/invites
```

建议默认参数：

```json
{
  "expiresInMinutes": 1440,
  "maxUses": 7
}
```

创建成功后展示：

* 邀请码；
* 复制邀请码；
* 微信分享；
* 生成小程序码或二维码；
* 过期时间；
* 剩余可使用次数。

邀请码原文只在创建时获取一次。

## 8.3 输入邀请码加入

用户可以在“加入家庭”页面输入邀请码。

流程：

```text
输入邀请码
→ GET /api/v1/family-invites/{code}
→ 展示家庭名称和成员数量
→ 用户确认
→ POST /api/v1/family-invites/{code}/join
```

异常状态：

* 邀请码不存在；
* 邀请码已过期；
* 邀请码已撤销；
* 邀请码已用完；
* 家庭已满 8 人；
* 用户已经是家庭成员。

如果已经加入，应直接引导进入家庭，而不是停留在错误页。

## 8.4 扫码加入

二维码或小程序码最终解析为邀请码或加入路径。

扫码后的加入流程与输入邀请码相同。

## 8.5 设置管理员

仅管理员可操作。

调用：

```http
PATCH /api/v1/families/{familyId}/members/{userId}
```

请求：

```json
{
  "role": "admin"
}
```

取消管理员：

```json
{
  "role": "member"
}
```

最后一名管理员不能被降级。

## 8.6 移除成员

仅管理员可操作。

调用：

```http
DELETE /api/v1/families/{familyId}/members/{userId}
```

交互要求：

* 操作前二次确认；
* 明确展示被移除成员名称；
* 管理员不能通过该入口移除自己；
* 最后一名管理员不能被移除。

## 8.7 主动退出家庭

调用：

```http
POST /api/v1/families/{familyId}/leave
```

要求：

* 二次确认；
* 提示退出后无法查看家庭数据；
* 最后一名管理员不能退出；
* 管理员需要先指定其他管理员。

退出成功后：

* 从本地家庭列表移除；
* 切换至其他家庭；
* 没有其他家庭时进入空状态页。

## 8.8 邀请管理

管理员可以调用：

```http
GET /api/v1/families/{familyId}/invites
```

查看：

* 邀请状态；
* 创建时间；
* 过期时间；
* 已使用次数；
* 最大使用次数。

撤销邀请：

```http
POST /api/v1/families/{familyId}/invites/{inviteId}/revoke
```

列表中不展示邀请码原文，因为 Core 不保存邀请码明文。

# 9. 日程功能

## 9.1 日程列表

调用：

```http
GET /api/v1/families/{familyId}/events
```

第一版建议提供两种展示：

```text
日期列表
月历 + 当日列表
```

默认进入时展示：

* 今天；
* 未来近期日程；
* 全天日程；
* 普通时间日程。

可筛选：

* 时间范围；
* 全部参与人；
* 只看我的日程；
* 指定家庭成员。

只看我的日程：

```http
GET /api/v1/families/{familyId}/events?attendeeId=me
```

## 9.2 日程卡片

日程列表项展示：

* 标题；
* 日期；
* 开始和结束时间；
* 全天标识；
* 地点；
* 参与人头像；
* 已取消状态，可选。

## 9.3 日程详情

调用：

```http
GET /api/v1/families/{familyId}/events/{eventId}
```

展示：

* 标题；
* 描述；
* 开始时间；
* 结束时间；
* 是否全天；
* 地点；
* 参与人；
* 创建人；
* 最后修改人；
* 创建和修改时间。

提供：

* 编辑；
* 删除。

第一版家庭所有有效成员均可编辑和删除日程。

## 9.4 创建日程

表单字段：

```text
标题：必填
描述：可选
全天：开关
开始日期/时间：必填
结束日期/时间：必填
参与人：可多选
地点：可选文本
```

普通时间日程示例：

```json
{
  "summary": "足球训练",
  "description": "携带水杯和训练服",
  "start": "2026-07-25T16:00:00+08:00",
  "end": "2026-07-25T18:00:00+08:00",
  "isAllDay": false,
  "timezone": "Asia/Shanghai",
  "attendeeIds": [
    "usr_KK",
    "usr_DAD"
  ],
  "location": "浦东足球公园"
}
```

调用：

```http
POST /api/v1/families/{familyId}/events
```

## 9.5 全天日程

全天日程只选择日期，不选择具体时间。

前端应清楚表达结束日期规则。

建议用户界面显示为包含式日期，例如：

```text
7 月 25 日至 7 月 27 日
```

提交给 Core 时转换成结束日期不包含的形式：

```json
{
  "start": "2026-07-25",
  "end": "2026-07-28",
  "isAllDay": true
}
```

## 9.6 参与人选择

参与人从当前家庭成员列表中选择。

支持：

* 不选择任何人；
* 选择自己；
* 选择多个家庭成员；
* 全选家庭成员。

前端提交 `userId`，不提交昵称作为身份。

## 9.7 编辑日程

调用：

```http
PATCH /api/v1/families/{familyId}/events/{eventId}
```

修改时携带当前版本号：

```json
{
  "summary": "足球比赛",
  "version": 2
}
```

如果返回版本冲突：

```text
该日程已被其他成员修改
```

提供：

* 重新加载；
* 查看最新内容；
* 用户重新编辑。

不要自动覆盖其他成员的修改。

## 9.8 删除日程

调用：

```http
DELETE /api/v1/families/{familyId}/events/{eventId}?version=2
```

要求：

* 二次确认；
* 删除成功后返回日程列表；
* 刷新首页近期日程。

## 9.9 第一版暂不支持

```text
重复日程
参与人接受或拒绝
外部参与人
附件
评论
外部日历同步
每位参与人独立提醒
```

# 10. 待办任务功能

## 10.1 待办列表

调用：

```http
GET /api/v1/families/{familyId}/tasks
```

默认展示：

```text
待完成任务
```

支持切换：

* 待完成；
* 已完成；
* 全部；
* 我的任务；
* 指定负责人。

只看我的任务：

```http
GET /api/v1/families/{familyId}/tasks?assigneeId=me
```

## 10.2 待办列表项

展示：

* 任务名称；
* 截止日期；
* 负责人头像；
* 完成状态；
* 是否逾期。

逾期属于前端展示状态：

```text
status = pending
且 due < 今天
```

不需要单独存储 `overdue` 状态。

## 10.3 创建待办

表单字段：

```text
任务名称：必填
描述：可选
截止日期：可选，只到天
负责人：可多选
```

请求：

```json
{
  "name": "购买足球鞋",
  "description": "周末比赛前购买",
  "due": "2026-07-25",
  "assigneeIds": [
    "usr_DAD"
  ]
}
```

调用：

```http
POST /api/v1/families/{familyId}/tasks
```

一个任务可以没有负责人，表示家庭公共待办。

## 10.4 待办详情

调用：

```http
GET /api/v1/families/{familyId}/tasks/{taskId}
```

展示：

* 任务名称；
* 描述；
* 截止日期；
* 当前状态；
* 负责人；
* 创建人；
* 最后修改人；
* 完成人；
* 完成时间；
* 创建和修改时间。

## 10.5 编辑待办

调用：

```http
PATCH /api/v1/families/{familyId}/tasks/{taskId}
```

请求中携带版本号：

```json
{
  "name": "购买新足球鞋",
  "due": "2026-07-26",
  "assigneeIds": [
    "usr_DAD",
    "usr_KK"
  ],
  "version": 2
}
```

支持：

* 修改名称；
* 修改描述；
* 修改截止日期；
* 清除截止日期；
* 修改负责人。

## 10.6 完成待办

在列表或详情页点击完成：

```http
POST /api/v1/families/{familyId}/tasks/{taskId}/complete
```

请求：

```json
{
  "version": 2
}
```

第一版任意家庭有效成员都可以完成任务，不要求必须是负责人。

完成后：

* 列表中显示已完成；
* 记录完成人；
* 记录完成时间；
* 从默认待完成列表移除。

## 10.7 恢复待办

已完成任务可以恢复：

```http
POST /api/v1/families/{familyId}/tasks/{taskId}/reopen
```

恢复后：

* 状态回到 `pending`；
* 清空完成人；
* 清空完成时间。

## 10.8 删除待办

调用：

```http
DELETE /api/v1/families/{familyId}/tasks/{taskId}?version=2
```

要求二次确认。

## 10.9 第一版暂不支持

```text
子任务
优先级
标签
评论
附件
任务依赖
每位负责人分别完成
重复任务
```

# 11. 首页需求

## 11.1 有家庭时

首页顶部：

```text
当前家庭名称
家庭切换入口
成员头像
家庭管理入口
```

首页主要区域：

### 今日日程

展示：

* 今天的全天日程；
* 今天的普通日程；
* 查看全部日程入口；
* 快速新增日程。

### 近期日程

建议展示未来 7 天内最近若干项。

### 待完成任务

建议展示：

* 已逾期；
* 今天截止；
* 近期截止；
* 无截止日期的任务。

### 快速操作

```text
新建日程
新建待办
邀请家人
```

邀请家人仅管理员显示。

## 11.2 没有家庭时

空状态文案建议：

```text
创建一个家庭，和家人一起管理日程与待办。
```

操作：

```text
创建家庭
加入家庭
```

## 11.3 加载失败

首页各模块应允许局部失败。

例如日程加载失败时：

* 家庭信息仍然可以展示；
* 待办仍然可以展示；
* 日程区域显示重试按钮。

不应因为一个接口失败导致整个首页空白。

# 14. 网络与错误处理

## 14.1 统一请求封装

小程序应有统一 Core API 请求层，负责：

* 添加 `Authorization`；
* 添加 `x-request-id`，可选；
* 解析 `{ data }`；
* 解析 `{ error }`；
* 处理 `401` 自动重新登录；
* 防止同一时间重复刷新 Token；
* 网络超时；
* 请求重试；
* 错误日志。

## 14.2 不应自动重试的请求

以下写操作不能无条件自动重试：

```text
创建家庭
创建日程
创建待办
完成任务
加入家庭
生成邀请码
```

否则可能导致重复创建。

后续建议 Core 支持：

```http
Idempotency-Key: <随机值>
```

小程序写请求可携带幂等键。

## 14.3 常见错误展示

### 401

```text
登录状态已过期，正在重新登录。
```

### 403

```text
你没有权限执行此操作。
```

家庭数据访问时可显示：

```text
你已不是该家庭成员，无法查看相关内容。
```

### 404

```text
内容不存在或已被删除。
```

### 409 版本冲突

```text
内容已被其他家庭成员修改，请刷新后重试。
```

### 家庭人数上限

```text
该家庭已有 8 名成员，暂时无法加入。
```

### 创建家庭上限

```text
每个用户最多创建 3 个家庭。
```

# 15. 权限与界面控制

## 15.1 普通家庭成员

可以：

* 查看家庭资料；
* 查看成员；
* 查看日程；
* 创建、编辑、删除日程；
* 查看待办；
* 创建、编辑、完成、恢复、删除待办；
* 主动退出家庭。

不可以：

* 修改家庭资料；
* 邀请成员；
* 撤销邀请；
* 设置管理员；
* 移除成员。

## 15.2 家庭管理员

除普通成员能力外，还可以：

* 修改家庭资料；
* 创建邀请码；
* 查看邀请记录；
* 撤销邀请码；
* 设置和取消管理员；
* 移除成员。

## 15.3 前端权限控制原则

前端根据家庭 API 返回的：

```text
currentUserRole
```

控制按钮显示。

但前端权限控制只用于交互优化，Core 必须再次校验权限。

# 20. 非功能需求

## 20.1 性能

目标：

* 首页首次可用内容尽快出现；
* 家庭、日程、待办可以并行加载；
* 切换家庭后优先显示骨架屏；
* 不等待所有模块成功后才展示页面；
* 防止重复点击导致重复提交。

## 20.2 安全

* 所有家庭数据访问必须经过 Core；
* 小程序前端不能直接访问 D1；
* 小程序前端不能持有服务密钥；
* 不信任客户端传入的当前用户 ID；
* `userId` 从 JWT 中取得；
* 家庭权限由 Core 的成员关系判断；
* 分享链接不能绕过权限。

## 20.3 可用性

* 写操作期间按钮进入加载状态；
* 避免重复提交；
* 删除和退出需要确认；
* 版本冲突不能静默覆盖；
* 网络中断时保留用户尚未提交的表单内容；
* 日期、时间和全天状态切换时避免数据丢失。

## 20.4 时区

第一版默认使用：

```text
Asia/Shanghai
```

即使用户位于其他地区，家庭日程默认仍可按家庭设置时区处理。

后续可以给家庭增加默认时区字段。

普通日程必须携带明确时区。

待办截止日期只表示家庭日期，不进行 UTC 转换。

## 20.5 数据量

第一版不需要复杂离线数据库。

建议：

* 日程按时间范围查询；
* 待办按状态分页；
* 成员列表一次完整加载；
* 家庭列表一次完整加载。
