# 日程与待办搜索开发约定

本文是 HomeMew 微信小程序实现日程、待办搜索时的开发说明。正式字段、路径和响应结构仍以 `apps/core/openapi.yaml` 为唯一 API 契约。

## 1. 已实现的接口

### 搜索日程

```http
GET /api/v1/families/{familyId}/events
  ?startDate=2026-01-01
  &endDateExclusive=2027-01-01
  &timezone=Asia/Shanghai
  &q=足球
  &limit=20
```

日程列表仍然必须提供：

- `startDate`：查询窗口开始日期，包含；
- `endDateExclusive`：查询窗口结束日期，不包含；
- `timezone`：可选，确定定时日程与日期窗口的重叠关系；省略时使用家庭时区。

`q` 只在这个日期窗口内搜索，不是跨全部历史记录的无限范围搜索。单次日期窗口最多 366 天。

匹配字段：

- `summary`；
- `description`；
- `location`。

### 搜索待办

```http
GET /api/v1/families/{familyId}/tasks
  ?status=pending
  &assigneeId=me
  &q=作业
  &sort=due_asc
  &limit=20
```

匹配字段：

- `name`；
- `description`。

搜索可以与已有的状态、负责人、截止日期、排序条件组合。

## 2. `q` 参数规则

- `q` 可选；不传时行为与原列表接口完全一致。
- Core 会先去除首尾空格。
- 去除空格后必须包含 1 至 100 个字符。
- 空字符串、全空格或超过 100 个字符返回 `400 / INVALID_REQUEST`。
- 使用子串匹配，不要求完整词匹配。
- 英文 ASCII 字母大小写不敏感；中文按原文子串匹配。
- `%`、`_` 等字符按普通字符处理，不是通配符。
- 搜索不改变原列表排序规则，也不返回相关度分值或高亮片段。

## 3. 分页与游标

搜索结果继续使用：

```json
{
  "data": {
    "items": [],
    "nextCursor": null
  }
}
```

`cursor` 与完整查询条件绑定，包括：

- 家庭；
- 日程日期窗口和查看时区；
- 状态；
- 参与人或负责人；
- 截止日期条件；
- 排序方式；
- `q`。

只要搜索词或任一筛选条件变化，小程序必须：

1. 清空当前结果；
2. 丢弃旧 `cursor`；
3. 从第一页重新请求。

不得把旧搜索词返回的游标用于新搜索词，否则 Core 返回 `400 / INVALID_REQUEST`。

## 4. 小程序 Service 调用

当前 Service 已暴露 `q`：

```ts
fetchEventsPage(familyId, {
  startDate,
  endDateExclusive,
  timezone,
  attendeeId,
  status: 'active',
  q: keyword,
  limit: 20,
});

listTasks(familyId, {
  status: 'pending',
  assigneeId: 'me',
  q: keyword,
  sort: 'due_asc',
});
```

调用方必须传原始搜索文本，由 Service 负责 URL 编码；不要手工拼接未经编码的 `q`。

列表页不要先拉取全部数据再在客户端过滤。搜索、成员范围、状态和日期条件应统一交给 Core，以保证分页结果和多端行为一致。

## 5. 推荐交互

### 输入与请求

- 输入框变化后约 300 毫秒防抖再请求。
- 输入为空时退出搜索态，恢复普通列表，不向 Core 发送空 `q`。
- 点击清除后立即清空搜索词、结果和游标，并重新加载普通列表。
- 用请求序号或等价机制忽略较早请求的迟到响应，避免快速输入时旧结果覆盖新结果。
- 搜索中、无结果、网络失败分别展示独立状态。

### 日程搜索范围

日程 API 必须有日期窗口，小程序需要明确当前搜索范围：

- 在普通日程页内搜索：沿用当前页面正在浏览或预加载的日期窗口；
- 做独立的“搜索日程”页面：默认可选择一个不超过 366 天的合理窗口，并允许用户调整；
- 页面应展示当前范围，避免用户误以为搜索了全部历史和未来日程。

### 待办搜索范围

待办没有强制日期窗口。搜索时继续沿用页面当前状态与成员范围：

- 进行中页面使用 `status=pending`；
- 已完成页面使用 `status=completed`；
- “我的待办”使用 `assigneeId=me`；
- 全家范围不传 `assigneeId`。

## 6. 典型错误处理

| 场景 | Core 响应 | 小程序处理 |
|---|---|---|
| 空白搜索词 | `400 INVALID_REQUEST` | 客户端不应发起请求 |
| 超过 100 字符 | `400 INVALID_REQUEST` | 限制输入并提示 |
| 游标与搜索条件不一致 | `400 INVALID_REQUEST` | 清空游标并从第一页重试一次 |
| 无家庭读取权限 | `403` | 清理当前家庭业务数据并刷新家庭列表 |
| Token 过期 | `401` | 统一登录刷新后只重试一次 |
| 无匹配结果 | `200`，`items=[]` | 展示“没有找到相关内容” |

## 7. 第一版验收标准

- 日程可命中标题、描述和地点。
- 待办可命中名称和描述。
- 搜索可与成员、状态、日期和排序条件组合。
- 修改关键词后不会继续使用旧游标。
- 快速输入时不会被迟到响应覆盖。
- 清空关键词后恢复普通列表。
- 日程搜索界面明确展示搜索日期范围。
- 搜索结果点击后进入现有详情页，不创建独立的数据模型。
