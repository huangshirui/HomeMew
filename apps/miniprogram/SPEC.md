# HomeMew 家事喵微信小程序需求

## 1. 产品定位

家事喵微信小程序是 HomeMew 面向家庭成员的主要图形化操作端。

主要用于：

* 用户登录和身份初始化；
* 创建或加入家庭；
* 管理家庭成员；
* 查看和维护家庭日程；
* 查看和维护家庭待办任务；
* 接收并打开通知对应的业务详情；
* 提供传统 GUI，补充智能助手自然语言交互不方便完成的操作。

小程序不是独立业务系统。

家庭、成员、日程、待办等业务数据统一存储在 HomeMew Core 中，小程序通过 Core API 读写数据。

---

# 2. 第一版用户范围

初期主要服务一个家庭：

```text
1 个主要家庭
最多 8 名家庭成员
```

系统能力仍支持：

```text
一个微信用户最多创建 3 个家庭
一个用户可以加入多个家庭
```

用户进入小程序后，可以在自己已加入的家庭之间切换。

# 3. 系统架构

## 3.1 推荐调用链路

### 登录和身份初始化

```text
微信小程序
→ 微信云函数
→ 获取可信 openid
→ 查询微信身份与 HomeMew user_id 的映射
→ 必要时调用 Core 创建用户
→ 签发短期 HomeMew JWT
→ 返回小程序
```

### 日常业务调用

```text
微信小程序
→ 携带 HomeMew JWT
→ 直接调用 Cloudflare Worker Core API
```

### 微信平台专属能力

```text
微信小程序
→ 微信云函数
→ 微信服务端 API
```

包括：

* 获取可信微信身份；
* 生成小程序码；
* 获取微信平台访问令牌；
* 发送订阅消息；
* 解密微信敏感数据；
* 其他必须使用微信服务端凭证的操作。

## 3.2 小程序不应保存

```text
JWT_SECRET
Core 服务 Token
n8n 服务 Token
微信 appsecret
企业微信 secret
```

小程序只保存短期用户访问 Token。

# 4. 身份与登录

## 4.1 首次进入

用户第一次打开小程序时，小程序自动调用登录云函数。

登录云函数：

1. 从微信运行环境取得 `openid`；
2. 查询身份映射；
3. 如果不存在映射，调用 Core 创建 HomeMew 用户；
4. 保存 `openid → HomeMew user_id` 映射；
5. 签发短期用户 JWT；
6. 返回登录结果。

返回建议：

```json
{
  "accessToken": "eyJ...",
  "expiresAt": "2026-07-21T10:00:00.000Z",
  "isNewUser": true
}
```

已有身份映射登录时，云函数会先使用用户 JWT 请求 `GET /api/v1/me`。只有 Core 明确返回
`404/USER_NOT_FOUND` 时才重建 Core 用户并原位更新映射；401、403、超时和 5xx 均作为登录
错误返回，避免因临时故障创建重复用户。

定时日程统一提交规范 UTC `startAt/endAt`，`startTimezone/endTimezone` 仅作为端点显示元数据；
全天日程只提交 `startDate/endDateExclusive`。待办截止日期使用纯日期 `dueDate`。

## 4.2 获取用户信息

登录完成后调用：

```http
GET /api/v1/me
```

用于获取：

* HomeMew 用户 ID；
* 昵称；
* 头像；
* 用户状态。

## 4.3 用户资料与默认资料

首次识别到一个新的微信身份时，HomeMew 应用后端直接创建可用的 LifeSpace 用户，并分配默认昵称：

```text
微信用户xxxxxx
```

用户尚未上传头像时，小程序统一展示本地默认头像。默认资料不会阻塞首次使用：用户可以直接浏览首页、邀请页或其他深链功能，不会被强制跳转到资料授权/设置页。

用户需要修改资料时，从“我的 → 编辑资料”主动进入：

* 昵称：必填，保存时不允许为空；
* 头像：可选，可继续使用默认头像。

昵称通过：

```http
PATCH /api/v1/me
```

头像通过：

```http
PUT /api/v1/me/avatar
```

昵称用于家庭成员列表、日程参与人和待办负责人展示。

## 4.4 Token 过期

Core 返回 `401` 时：

```text
小程序重新调用登录云函数
→ 获取新 Token
→ 原请求自动重试一次
```

不建议第一版实现独立 Refresh Token。

## 4.5 用户被禁用

如果 Core 返回用户已被禁用：

* 清除本地 Token；
* 停止访问业务页面；
* 展示账号不可用提示；
* 不进入无限重试登录。

# 5. 小程序信息架构

建议第一版底部导航包含：

```text
首页
日程
待办
我的
```

家庭管理能力集中在「我的」与家庭详情页，首页只负责当前家庭的日常协作展示。

## 5.1 首页

首页用于展示「当前家庭」的近期核心信息，不承载家庭管理入口：

* 当前家庭头部（图片 / 名称 / 成员数 / 切换）；
* 家庭切换入口（仅当存在多个家庭时显示）；
* 今日日程（查看全部进入日程 Tab、快速新建）；
* 待完成任务（查看全部进入待办 Tab、快速新建）；
* 无家庭时的创建或加入引导。

首页面不再直接提供：创建家庭、加入家庭、家庭详情与成员、管理员等低频管理入口。

## 5.2 日程

提供：

* 纵向时间线列表（按日期分组、连续展示前后日期）；
* 折叠月历（默认折叠，展开后可点日期定位列表）；
* 成员日历选择（全家 / 我的 / 指定成员，按用户持久化）；
* 日程详情；
* 创建日程；
* 编辑日程；
* 删除日程。

## 5.3 待办

提供：

* 待完成列表；
* 已完成列表；
* 任务详情；
* 创建任务；
* 编辑任务；
* 完成任务；
* 恢复任务；
* 删除任务；
* 按负责人筛选。

## 5.4 我的

提供个人资料与家庭管理中心：

* 用户头像和昵称；
* 我的家庭列表（当前家庭显示「当前」标签，展示图片 / 名称 / 人数 / 角色）；
* 点击家庭行切换为当前家庭；
* 点击「管理 ›」进入家庭详情；
* 创建家庭（进入独立创建页）；
* 加入家庭；
* 关于 HomeMew；
* 调试信息入口，仅开发版本；
* 开发版本额外提供「清除本地登录状态」，用于重置身份。

微信小程序登录通常为静默恢复，不提供「退出登录」入口。

# 6. 启动流程

## 6.1 普通启动

```text
启动小程序
→ 恢复本地 Token
→ Token 不存在或即将过期则调用登录云函数
→ GET /api/v1/me
→ GET /api/v1/me/families
```

根据家庭数量处理：

### 没有家庭

展示：

```text
创建家庭
加入家庭
```

### 只有一个家庭

直接设置为当前家庭并进入首页。

### 多个家庭

优先恢复上次使用的家庭。

如果上次家庭已无权访问，则：

* 自动选择第一个有效家庭；
* 或展示家庭选择页。

## 6.2 从邀请链接进入

用户通过分享卡片、小程序码或二维码进入时，启动参数可能包含：

```text
code=HM-8K2Q-P7MX
```

流程：

```text
完成登录
→ GET /api/v1/family-invites/{code}
→ 展示邀请确认页
→ 用户确认
→ POST /api/v1/family-invites/{code}/join
→ 设置为当前家庭
→ 进入家庭首页
```

## 6.3 从通知进入

企业微信通知或未来小程序通知可能打开：

```text
pages/events/detail?id=evt_123&familyId=fam_123
```

或：

```text
pages/tasks/detail?id=tsk_123&familyId=fam_123
```

流程：

```text
完成登录
→ 调用对应详情 API
→ Core 校验家庭权限
→ 展示详情
```

如果用户已被移出家庭：

* 展示“你已无权查看该内容”；
* 不泄露日程或待办内容。

# 7. 家庭功能

## 7.1 获取家庭列表

调用：

```http
GET /api/v1/me/families
```

展示：

* 家庭名称；
* 家庭头像；
* 当前用户角色；
* 家庭成员数量。

## 7.2 创建家庭

入口（统一进入独立创建页 `/pages/family/create`）：

```text
首页无家庭状态 → 创建家庭
我的 → 创建家庭
```

表单字段：

```text
家庭名称：必填
家庭头像：可选
```

调用：

```http
POST /api/v1/families
```

若用户选择了头像，创建成功后用家庭头像上传接口补充：

```http
PUT /api/v1/families/{familyId}/avatar
```

创建成功后：

* 创建人自动成为管理员；
* 设置新家庭为当前家庭；
* 返回首页（当前家庭工作台）。

达到 3 个家庭创建上限时，展示明确提示。

## 7.3 家庭切换

家庭切换器展示当前用户加入的所有有效家庭。

切换后：

* 更新本地 `currentFamilyId`；
* 刷新首页；
* 刷新日程；
* 刷新待办；
* 刷新成员信息。

当前家庭 ID 只是界面上下文，不是权限凭据。

## 7.4 家庭详情

调用：

```http
GET /api/v1/families/{familyId}
```

页面结构（标准家庭设置页，突出家庭本身而非菜单）：

* 顶部家庭资料卡：家庭大图、名称、成员数 · 角色；管理员显示「编辑家庭资料」；
* 家庭管理分组：家庭成员（右侧展示人数）、邀请家人加入（仅管理员）；
* 危险操作分组：退出家庭。

## 7.5 修改家庭资料

仅管理员可进入独立的「编辑家庭资料」页（`/pages/family/edit`）。

编辑页提供：

* 点击图片更换家庭头像（即时上传）；
* 家庭名称输入框；
* 保存按钮。

保存时调用：

```http
PATCH /api/v1/families/{familyId}
```

头像通过独立接口上传：

```http
PUT /api/v1/families/{familyId}/avatar
```

支持修改：

* 家庭名称；
* 家庭头像。

普通成员不显示编辑入口。

即使前端错误展示，Core 仍必须返回 `403`。

# 8. 家庭成员功能

## 8.1 成员列表

调用：

```http
GET /api/v1/families/{familyId}/members
```

展示：

* 头像；
* 昵称；
* 管理员标识；
* 加入时间，可选。

管理员和普通成员都可以查看。

## 8.2 邀请成员

仅管理员可使用。

调用：

```http
POST /api/v1/families/{familyId}/invites
```

建议默认参数：

```json
{
  "expiresInMinutes": 1440,
  "maxUses": 7
}
```

创建成功后展示：

* 邀请码；
* 复制邀请码；
* 微信分享；
* 生成小程序码或二维码；
* 过期时间；
* 剩余可使用次数。

邀请码原文只在创建时获取一次。

## 8.3 输入邀请码加入

用户可以在“加入家庭”页面输入邀请码。

流程：

```text
输入邀请码
→ GET /api/v1/family-invites/{code}
→ 展示家庭名称和成员数量
→ 用户确认
→ POST /api/v1/family-invites/{code}/join
```

异常状态：

* 邀请码不存在；
* 邀请码已过期；
* 邀请码已撤销；
* 邀请码已用完；
* 家庭已满 8 人；
* 用户已经是家庭成员。

如果已经加入，应直接引导进入家庭，而不是停留在错误页。

## 8.4 扫码加入

二维码或小程序码最终解析为邀请码或加入路径。

扫码后的加入流程与输入邀请码相同。

## 8.5 设置管理员

仅管理员可操作。

调用：

```http
PATCH /api/v1/families/{familyId}/members/{userId}
```

请求：

```json
{
  "role": "admin"
}
```

取消管理员：

```json
{
  "role": "member"
}
```

最后一名管理员不能被降级。

## 8.6 移除成员

仅管理员可操作。

调用：

```http
DELETE /api/v1/families/{familyId}/members/{userId}
```

交互要求：

* 操作前二次确认；
* 明确展示被移除成员名称；
* 管理员不能通过该入口移除自己；
* 最后一名管理员不能被移除。

## 8.7 主动退出家庭

调用：

```http
POST /api/v1/families/{familyId}/leave
```

要求：

* 二次确认；
* 提示退出后无法查看家庭数据；
* 最后一名管理员不能退出；
* 管理员需要先指定其他管理员。

退出成功后：

* 从本地家庭列表移除；
* 切换至其他家庭；
* 没有其他家庭时进入空状态页。

## 8.8 邀请管理

管理员可以调用：

```http
GET /api/v1/families/{familyId}/invites
```

查看：

* 邀请状态；
* 创建时间；
* 过期时间；
* 已使用次数；
* 最大使用次数。

撤销邀请：

```http
POST /api/v1/families/{familyId}/invites/{inviteId}/revoke
```

列表中不展示邀请码原文，因为 Core 不保存邀请码明文。

# 9. 日程功能

## 9.1 日程列表

调用：

```http
GET /api/v1/families/{familyId}/events?startDate=2026-07-01&endDateExclusive=2026-08-01&timezone=Asia%2FShanghai
```

`timezone` 是「查看时区」：Core 用它把 `startDate/endDateExclusive` 换算成 UTC 查询窗口。
客户端必须使用同一个查看时区决定「日程属于哪一天」——包括列表分组、月历圆点和首页
「今天」判断。日程自身的 `startTimezone/endTimezone` 只是端点地点时区元数据
（例如航班出发地 / 到达地），只能作为详情与卡片上的时间标签，绝不能参与归组，
否则同一条日程会被分到 Core 查询窗口以外的另一天。

由于查询窗口与归组窗口语义一致，请求不得再前后额外扩几天；
「当前范围无日程」的判断也只统计真正落在范围内、能被展示的日程。

页面主体为纵向时间线列表：

* 日程按日期分组、按开始时间排列；
* 全天日程排在当日最前；
* 列表连续展示前后日期，不只显示选中某一天；
* 每条展示标题、时间、参与成员、地点；全家视角必须显示参与成员。

折叠月历：

* 默认折叠，仅显示当前月份、展开按钮和「今天」快捷入口；
* 展开后日期显示是否有日程，点日期滚动列表到该日期并自动折叠；
* 列表滚动时折叠条的月份标题同步变化。

成员日历选择（页面左上角）：

* 全家日历：查询全家的全部日程；
* 我的日历：`attendeeId=me`；
* 指定成员：`attendeeId={userId}`，成员列表从当前家庭动态加载；
* 按 (家庭, 用户) 持久化上次选择，下次进入直接恢复；
* 首次使用默认「我的日历」。

分段加载（时间窗口 + 窗口内游标）：

* 首次以今天为中心加载过去 7 天 + 未来 30 天，并自动定位到今天；
* 接近列表顶部 / 底部约 2~3 屏时，按 30 天窗口向前 / 向后预加载；
* 接口游标只用于窗口内部翻页，页面按时间窗口管理加载范围；
* 相邻窗口的重叠多日日程按 event id 去重；
* 向上插入历史数据时保持当前滚动位置不跳动；
* 浏览上限为今天前后各 365 天，到达后展示「已加载到最早 / 最晚」。

状态要求：首次加载骨架屏、向前 / 向后加载中、当前范围无日程、
网络失败可重试、切换成员后回到今天并重新加载、
新建 / 修改 / 删除日程后保持当前成员范围和滚动位置。

只看我的日程：

```http
GET /api/v1/families/{familyId}/events?startDate=2026-07-01&endDateExclusive=2026-08-01&timezone=Asia%2FShanghai&attendeeId=me
```

## 9.2 日程卡片

日程列表项展示：

* 标题；
* 日期；
* 开始和结束时间；
* 全天标识；
* 地点；
* 参与人头像；
* 已取消状态，可选。

## 9.3 日程详情

调用：

```http
GET /api/v1/families/{familyId}/events/{eventId}
```

展示：

* 标题；
* 描述；
* 开始时间；
* 结束时间；
* 是否全天；
* 地点；
* 参与人；
* 创建人；
* 最后修改人；
* 创建和修改时间。

提供：

* 编辑；
* 删除。

第一版家庭所有有效成员均可编辑和删除日程。

## 9.4 创建日程

表单字段：

```text
标题：必填
描述：可选
全天：开关
开始日期/时间：必填
结束日期/时间：必填
参与人：可多选
地点：可选文本
```

普通时间日程示例：

```json
{
  "summary": "足球训练",
  "description": "携带水杯和训练服",
  "startAt": "2026-07-25T08:00:00.000Z",
  "endAt": "2026-07-25T10:00:00.000Z",
  "isAllDay": false,
  "startTimezone": "Asia/Shanghai",
  "endTimezone": "Asia/Shanghai",
  "attendeeIds": [
    "usr_KK",
    "usr_DAD"
  ],
  "location": "浦东足球公园"
}
```

调用：

```http
POST /api/v1/families/{familyId}/events
```

## 9.5 全天日程

全天日程只选择日期，不选择具体时间。

前端应清楚表达结束日期规则。

建议用户界面显示为包含式日期，例如：

```text
7 月 25 日至 7 月 27 日
```

提交给 Core 时转换成结束日期不包含的形式：

```json
{
  "isAllDay": true,
  "startDate": "2026-07-25",
  "endDateExclusive": "2026-07-28"
}
```

## 9.6 参与人选择

参与人从当前家庭成员列表中选择。

支持：

* 不选择任何人；
* 选择自己；
* 选择多个家庭成员；
* 全选家庭成员。

前端提交 `userId`，不提交昵称作为身份。

## 9.7 编辑日程

调用：

```http
PATCH /api/v1/families/{familyId}/events/{eventId}
```

修改时携带当前版本号：

```json
{
  "summary": "足球比赛",
  "version": 2
}
```

如果返回版本冲突：

```text
该日程已被其他成员修改
```

提供：

* 重新加载；
* 查看最新内容；
* 用户重新编辑。

不要自动覆盖其他成员的修改。

## 9.8 删除日程

调用：

```http
DELETE /api/v1/families/{familyId}/events/{eventId}?version=2
```

要求：

* 二次确认；
* 删除成功后返回日程列表；
* 刷新首页近期日程。

## 9.9 第一版暂不支持

```text
重复日程
参与人接受或拒绝
外部参与人
附件
评论
外部日历同步
每位参与人独立提醒
```

# 10. 待办任务功能

## 10.1 待办列表

调用：

```http
GET /api/v1/families/{familyId}/tasks
```

默认展示：

```text
待完成任务
```

支持切换：

* 待完成；
* 已完成；
* 全部；
* 我的任务；
* 指定负责人。

只看我的任务：

```http
GET /api/v1/families/{familyId}/tasks?assigneeId=me
```

## 10.2 待办列表项

展示：

* 任务名称；
* 截止日期；
* 负责人头像；
* 完成状态；
* 是否逾期。

逾期属于前端展示状态：

```text
status = pending
且 dueDate < 今天
```

不需要单独存储 `overdue` 状态。

## 10.3 创建待办

表单字段：

```text
任务名称：必填
描述：可选
截止日期：可选，只到天
负责人：可多选
```

请求：

```json
{
  "name": "购买足球鞋",
  "description": "周末比赛前购买",
  "dueDate": "2026-07-25",
  "assigneeIds": [
    "usr_DAD"
  ]
}
```

调用：

```http
POST /api/v1/families/{familyId}/tasks
```

一个任务可以没有负责人，表示家庭公共待办。

## 10.4 待办详情

调用：

```http
GET /api/v1/families/{familyId}/tasks/{taskId}
```

展示：

* 任务名称；
* 描述；
* 截止日期；
* 当前状态；
* 负责人；
* 创建人；
* 最后修改人；
* 完成人；
* 完成时间；
* 创建和修改时间。

## 10.5 编辑待办

调用：

```http
PATCH /api/v1/families/{familyId}/tasks/{taskId}
```

请求中携带版本号：

```json
{
  "name": "购买新足球鞋",
  "dueDate": "2026-07-26",
  "assigneeIds": [
    "usr_DAD",
    "usr_KK"
  ],
  "version": 2
}
```

支持：

* 修改名称；
* 修改描述；
* 修改截止日期；
* 清除截止日期；
* 修改负责人。

## 10.6 完成待办

在列表或详情页点击完成：

```http
POST /api/v1/families/{familyId}/tasks/{taskId}/complete
```

请求：

```json
{
  "version": 2
}
```

第一版任意家庭有效成员都可以完成任务，不要求必须是负责人。

完成后：

* 列表中显示已完成；
* 记录完成人；
* 记录完成时间；
* 从默认待完成列表移除。

## 10.7 恢复待办

已完成任务可以恢复：

```http
POST /api/v1/families/{familyId}/tasks/{taskId}/reopen
```

恢复后：

* 状态回到 `pending`；
* 清空完成人；
* 清空完成时间。

## 10.8 删除待办

调用：

```http
DELETE /api/v1/families/{familyId}/tasks/{taskId}?version=2
```

要求二次确认。

## 10.9 第一版暂不支持

```text
子任务
优先级
标签
评论
附件
任务依赖
每位负责人分别完成
重复任务
```

# 14. 网络与错误处理

## 14.1 统一请求封装

小程序应有统一 Core API 请求层，负责：

* 添加 `Authorization`；
* 添加 `x-request-id`，可选；
* 解析 `{ data }`；
* 解析 `{ error }`；
* 处理 `401` 自动重新登录；
* 防止同一时间重复刷新 Token；
* 网络超时；
* 请求重试；
* 错误日志。

## 14.2 不应自动重试的请求

以下写操作不能无条件自动重试：

```text
创建家庭
创建日程
创建待办
完成任务
加入家庭
生成邀请码
```

否则可能导致重复创建。

后续建议 Core 支持：

```http
Idempotency-Key: <随机值>
```

小程序写请求可携带幂等键。

## 14.3 常见错误展示

### 401

Access Token 过期属于内部基础设施状态，正常情况下通过 `wx.login()` + HomeMew Backend 静默换票，不向用户展示“登录/重新登录”。

GET 等可安全重放的请求允许在静默换票后自动重试一次；非幂等写请求不盲目重放，若已收到 401，则先静默刷新凭证，并提示：

```text
请求未完成，请重试。
```

### 403

```text
你没有权限执行此操作。
```

家庭数据访问时可显示：

```text
你已不是该家庭成员，无法查看相关内容。
```

### 404

```text
内容不存在或已被删除。
```

### 409 版本冲突

```text
内容已被其他家庭成员修改，请刷新后重试。
```

### 家庭人数上限

```text
该家庭已有 8 名成员，暂时无法加入。
```

### 创建家庭上限

```text
每个用户最多创建 3 个家庭。
```

# 20. 非功能需求

## 20.1 性能

目标：

* 首页首次可用内容尽快出现；
* 家庭、日程、待办可以并行加载；
* 切换家庭后优先显示骨架屏；
* 不等待所有模块成功后才展示页面；
* 防止重复点击导致重复提交。

## 20.2 安全

* 所有家庭数据访问必须经过 Core；
* 小程序前端不能直接访问 D1；
* 小程序前端不能持有服务密钥；
* 不信任客户端传入的当前用户 ID；
* `userId` 从 JWT 中取得；
* 家庭权限由 Core 的成员关系判断；
* 分享链接不能绕过权限。

## 20.3 可用性

* 写操作期间按钮进入加载状态；
* 避免重复提交；
* 删除和退出需要确认；
* 版本冲突不能静默覆盖；
* 网络中断时保留用户尚未提交的表单内容；
* 日期、时间和全天状态切换时避免数据丢失。

## 20.4 时区

第一版默认使用：

```text
Asia/Shanghai
```

即使用户位于其他地区，家庭日程默认仍可按家庭设置时区处理。

后续可以给家庭增加默认时区字段。

普通日程必须携带明确时区。

待办截止日期只表示家庭日期，不进行 UTC 转换。

## 20.5 数据量

第一版不需要复杂离线数据库。

建议：

* 日程按时间范围查询；
* 待办按状态分页；
* 成员列表一次完整加载；
* 家庭列表一次完整加载。
